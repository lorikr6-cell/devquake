# DevQuake — project memory for Claude Code

DevQuake is a Next.js 16 host platform at `devquake.com`. Independent **plugins** live in
`plugins/<id>/` and are served on their own subdomain `<id>.devquake.com`.

## Stack

pnpm workspaces + Turborepo · Next.js 16 (App Router, `proxy.ts`) · React 19 · TypeScript (strict)
· Tailwind CSS v4 · Vitest. Node ≥ 20.9. Dev machine is **Windows** (repo at `D:\Work\devquake`).

## Layout

```
apps/host/            Next.js host app (root domain + plugin mount points)
packages/plugin-sdk/  Plugin contract: types, definePlugin, route matcher  ← public API
packages/ui/          Shared presentational components
packages/tsconfig/    Shared TS configs
plugins/<id>/         One folder per plugin (a workspace package)
templates/plugin/     Template copied by `pnpm new:plugin`
scripts/              Registry generator, plugin generator, setup
docs/                 Architecture, guides, ADRs, plugin index
db/migrations/        MySQL schema (Hostinger), applied in order; see db/README.md
```

## Commands (run from repo root)

- `pnpm dev` — host at http://localhost:3000, plugins at http://<id>.localhost:3000
- `pnpm new:plugin <id> "Name"` — scaffold a plugin (then `pnpm install`)
- `pnpm db:migrate` · `pnpm admin:create` — database migrations and admin account (`db/README.md`)
- `pnpm registry` — regenerate `apps/host/src/plugins/*.generated.ts`
- `pnpm typecheck` · `pnpm test` · `pnpm build` · `pnpm format`
- Single package: `pnpm --filter @devquake/<name> <script>`

## Environments & deployment

- Local: http://localhost:3000, plugins at http://<id>.localhost:3000
- Production: https://devquake.com, plugins at https://<id>.devquake.com (Hostinger, hPanel)
- Deploy = merge to `main`. CI (`check`, then `deploy-bundle`) force-pushes a prebuilt npm bundle
  to the `deploy` branch; Hostinger redeploys it. Details: `docs/guides/deployment.md`, ADR 0003.

## How a request flows

`blog.devquake.com/posts/1` → `apps/host/src/proxy.ts` rewrites to `/plugin-host/blog/posts/1`
→ `plugin-host/[plugin]/[[...path]]/page.tsx` loads the plugin from the generated registry,
matches `/posts/:id` in its `pages`, renders it. `/api/*` on a subdomain goes to `plugin-api`.
Details: `docs/architecture/routing-and-subdomains.md`.

## Hard rules

1. **Plugin isolation.** A plugin imports only from itself, `@devquake/plugin-sdk`,
   `@devquake/ui`, `next`, `react`, and its own deps. Never from `apps/host` or another plugin.
   The host never imports a specific plugin except through the generated registry.
2. **Never hand-edit `*.generated.ts`.** Run `pnpm registry`.
3. **The SDK is a public contract.** Changes to `packages/plugin-sdk/src/types.ts` need an ADR and
   must be backward compatible unless explicitly approved. Use the `architect` agent.
4. **Next.js 16 conventions**: `params`/`searchParams` are Promises; request interception lives in
   `proxy.ts` (not `middleware.ts`); Server Components by default.
5. **Secrets**: never read, print or commit `.env*` files (except `.env.example`).
6. **Git**: small, focused commits using Conventional Commits (`feat(plugin-blog): ...`,
   `fix(host): ...`, `docs: ...`). Never force-push. Ask before pushing.
7. Before declaring work done: `pnpm typecheck` and `pnpm test` pass.
8. The `deploy` branch is generated by CI (`scripts/assemble-deploy.mjs`). Never commit to it.
   Deploying = merging to `main`.
9. The owner control panel is `/admin-cp` (root domain only). Never link to it from the site,
   and never put database credentials anywhere but env vars (`MAIN_DB_*`).

## Documentation policy (mandatory)

Docs are part of the change, not a follow-up. When you change behaviour, update in the same task:

- Plugin change → `plugins/<id>/README.md` (route table) + `CHANGELOG.md` + `CLAUDE.md` notes.
- Host/SDK/architecture change → the relevant file in `docs/architecture/`.
- Significant decision → new ADR in `docs/adr/` (use the `/adr` skill).
- New plugin → row in `docs/plugins/README.md` (the generator adds it).
  Use the `docs-keeper` agent for larger doc updates.

## Agents & skills (in `.claude/`)

Agents: `architect`, `plugin-builder`, `code-reviewer`, `test-engineer`, `docs-keeper`.
Skills: `/new-plugin`, `/adr`, `/update-docs`, `/review`, `/ship`.
Typical flow for a feature: architect (plan) → plugin-builder (build) → test-engineer →
code-reviewer → docs-keeper → `/ship`.
